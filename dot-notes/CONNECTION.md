# dot 接入状态与适配器约定

## 事实与阻碍

2026-10-23：通过只读事件源列表检查，当前返回 GitHub、Slack、Gmail；没有本记事本事件源。已搜索本会话可调用的连接/插件工具，没有可读取自定义插件管理入口状态或为这个记事本取得现有 dot 收件 URL 的接口。这只说明现有工具和事件源不足，**不是账户已被拒绝，也不能推断账户绝对不支持自定义插件**。

官方文档说明 MCP Events 支持 dots，需 MCP 2.0（2026-07-28）、事件发现、订阅/取消订阅、回调验证和签名 webhook。回调与签名秘密由订阅提供，不是凭空填写的固定 OpenAI endpoint。2xx 只确认接收，处理异步。
来源：[MCP Events](https://developers.openai.com/plugins/build/mcp-events)。

当前没有创建插件、生成凭证、创建订阅、部署服务或投递任何笔记。没有权限拒绝或结果不明的外部变更。阻碍是缺少可验证的接入入口和已授权配置，不是常规设计待确认。

## 已实现接口

`src/core.js` 的 Service 接收适配器：

```text
connected: boolean
send({noteId, version, key, snapshot: {title, body}})
  -> Promise<{key, status: "accepted", receiptId}>
```

生产包固定使用 `disconnected`，不会进行网络请求。测试中的适配器只用于注入网络失败、超时和回执，不随生产包发布。HTTP 客户端还未实现，因为真实地址、身份绑定和收件协议未确定。

key 为笔记 ID 与提交版本的组合，同一快照重试沿用 key。新提交前先将快照和 pending 状态保存，经读取核验后才能调用适配器。请求发出后超时/不匹配回执/异常都记为 unknown，不声称未到达。已接收不重复提交。重启见到 sending 也按未知结果显示，待用户主动重试。此版本的重试可以重新发起同一 key；未来服务必须提供持久化幂等保证，不能仅依赖客户端状态。

接受回执只推进“服务已接收”，没有代码伪造“dot 已处理”。未来若能取得可信的处理回执，应额外验证目标绑定、key 与任务身份后再设计这一状态；若官方没有提供该回执，就一直保留“处理未确认”。

## 最小可验证接入工作

1. 在用户账户核实自定义插件入口可用，并确定绑定的是用户已有 dot，不另建无上下文聊天。
2. 在批准的主机部署最小 MCP Events 桥接服务，持久保存订阅、授权、key 与回执。复用记事本数据层不等于已有同步服务能代替这个桥接服务。
3. 通过安全界面配置设备认证；签名秘密仅存服务端，不在插件源码中或聊天里放密钥。
4. 经授权安装 ChatGPT 自定义插件、创建目标 dot 订阅；验证回调地址与签名，防 SSRF，禁止重定向，按文档设置重试/过期规则。
5. 接入客户端适配器，发送前检查完整事件 UTF-8 字节数不超过 256 KiB；超过时明确拒绝，不截断笔记。拒绝错误身份/错误回执/错误目标，服务按 key 幂等接收。
6. 获准后只用无敏感测试笔记做端到端验收；检查实际出现在正确现有 dot、重复请求不产生重复动作，以及断网/重启恢复。

需要的外部授权分别为服务部署及可能费用、插件安装、持久凭证配置、订阅创建和无敏感测试投递。当前工程已完成无需这些权限的部分；不能把普通 API key、GitHub/Slack/Gmail 事件源或新聊天当作绕过路径。
